# P82 — Full-domain public detector replay, without labels (preregistered)

Registered 12 November 2026 UTC, after completed P81 one-image pilot and before any P82 inference. Objective: close the raw-image-to-detector-candidates reproducibility gap by running all four published Mask R-CNN FP16 checkpoints on all 180 original unlabelled official test JPEGs. This is an incremental release audit, not a new model, hidden-test tuning or a claim of improved Panoptic Quality.

Frozen inputs and order: sorted 180 JPEG filenames, all four blocks F1, F2, F3, F4 (no fold selection based on accuracy), each in original and horizontal-reflection views at 1024 pixels. Use the exact published filseg build_model/predict_files source after P81 import repair, no CUDA autocast or TF32, published SHA256-bound weights loaded strictly as FP32 parameters, and identical preprocessing and reflection inversion for every image. Compare proposal-count, same-index bounding-box identity and crop-byte equality descriptively with the trusted archived P69 FP32 CPU proposals, without selecting thresholds. The known P81 finding that quantized weights differ in crop pixels must not be concealed or used to revise the plan.

Primary gate: every original filename appears once in each fold; valid image and weight checksums; every output has two views with valid crop geometry; atomic per-image files, crash-resumable receipts and a complete per-fold manifest. No proposal equality to FP32 is guaranteed or required for a valid negative result. A stopped run may resume from verified per-image output without recomputing successful items, but cannot silently overwrite any receipt or partially written file.

Use only GPU0 UUID GPU-b2046dc8-91f7-fd8a-b237-96bb9e293d14, with exclusive supervisor.lock, preflight nvidia-smi, at most one CUDA process. GPU1 must remain untouched. Resource budget: <=8 GiB GPU0 VRAM target, <=8 GiB new host memory, <=2 GiB HDD for new outputs, <=1,500 seconds wall time, CPU workload <=2 cores, no large writes on the 97%-full /mnt/datos SSD. Preexisting CPU PQ scoring may proceed in parallel.

Do not access any competition test annotations, make Kaggle submissions, compare leaderboard variants, or infer PQ from predicted masks. After completing this stage, the final H6 selection, two refinement models, end-to-end notebook and official Google Form remain separate required tasks. JEV/Goldfish model-hypothesis approval is not claimed; P82 is a preregistered release reconstruction only.
